# Implementation Plan: RFC 9457 Error Responses

**Feature**: 001-problem-details-errors  
**Spec**: [spec.md](./spec.md)

## Technical Context

This .NET 10 backend uses ASP.NET Core controllers with Wolverine for CQRS and
StackExchange.Redis for data access. Controllers currently return simple DTOs
and errors often produce empty or inconsistent bodies. The requirement is to
standardize all `4xx`/`5xx` responses using the RFC 9457 "Problem Details"
format. ASP.NET Core provides built-in support via the `ProblemDetails` class
and associated middleware.

The project already references the necessary packages; no new NuGet dependencies
are required. The primary work will occur in `Program.cs` and possibly a small
custom `ProblemDetailsFactory` in `Web` or an extension method.

No domain entities or repository changes are required, so the work is mostly
in the Web API layer with companion unit tests.

## Phase 2: Implementation

### Tasks
1. **Modify Program.cs**
   - `builder.Services.AddProblemDetails();`
   - In middleware pipeline add `app.UseExceptionHandler();` and
     `app.UseStatusCodePages();` before `MapControllers()`.
   - Optionally configure global MVC options for validation key casing (if not
     already done).
2. **Create CustomProblemDetailsFactory** (in Web project)
   - Inherit from `ProblemDetailsFactory` and override methods to add
     `traceId` (primary), optional `traceparent`, and `requestPath` to
     `problemDetails.Extensions`.
   - Register singleton in DI.
3. **Unit tests**
   - Add tests verifying that `CustomProblemDetailsFactory` populates the
